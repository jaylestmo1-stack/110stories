## 2026-06-25 - The "Caring Archive" Pattern & GitHub Slugging
**Learning:** Static README-as-UI archives for sensitive content benefit from balancing technical metadata with proactive emotional support (Support Resources). Additionally, GitHub's anchor generation strips emojis and colons; internal navigation links must match these stripped slugs (e.g., `## ⚠️ Warning` maps to `#warning`) to "just work."
**Action:** Use a "Product Page" layout that pairs technical metadata with emotional support links. Always verify internal link integrity by stripping non-alphanumeric characters from header slugs.

## 2026-06-26 - Scent of Information & Archival Findability
**Learning:** In document-centric archives, providing a granular list of perspectives (the "Scent of Information") reduces the user's cognitive cost before downloading. Using the `download` attribute with a descriptive filename ensures that the asset remains identifiable and organized once it leaves the browser environment.
**Action:** Always provide qualitative metadata (like specific roles or themes) to help users evaluate content relevance, and use descriptive `download` attributes for all primary archival assets.

## 2026-06-27 - Information Promotion & Deep-Linking
**Learning:** Moving critical metadata from a table row into its own header (Information Promotion) significantly improves scannability and allows for deep-linking via the Quick Navigation bar. In content-heavy archives, this makes specific themes or perspectives much easier for researchers and students to find and share.
**Action:** Promote high-utility metadata (like perspectives, themes, or contributors) into dedicated sections with clear headers to enable better navigation and discoverability.
