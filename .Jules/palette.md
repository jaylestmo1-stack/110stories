## 2026-06-15 - README-as-UI for Static Archives
**Learning:** In content-centric repositories lacking a traditional web interface, the README serves as the primary user experience. UX can be significantly improved by treating the document as a "Product Page" with clear metadata (format, size, accessibility indicators) and navigation aids (internal anchors, visual cues for return-to-top). Emotional safety (content warnings) and researcher utility (one-click citations) are critical micro-UX wins for this context.
**Action:** Always prioritize clear asset metadata and directional navigation in documentation-only archives to reduce user interaction cost and improve predictability.

## 2026-06-20 - Emotional Hooks in Archival UX
**Learning:** For archives dealing with sensitive historical content, adding an 'emotional hook' (such as a representative quote) at the very top of the README-as-UI humanizes the data and provides immediate context. This bridges the gap between a technical file listing and the human stories contained within, improving the user's initial orientation and engagement.
**Action:** Consider prepending a poignant, grounded quote or summary to content-focused READMEs to establish immediate topical authority and empathy.

## 2026-06-21 - Trust and Scent of Information in Archival UX
**Learning:** For static archives, user trust can be bolstered by providing integrity verification (checksums) directly in the metadata. Additionally, expanding qualitative lists of content (the "scent of information")—such as specific roles or perspectives in a narrative collection—reduces the user's cognitive load and interaction cost before they decide to download and open the primary asset.
**Action:** Include short-hash checksums for large assets and provide granular, representative lists of content themes to improve predictability and trust.
